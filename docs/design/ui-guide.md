# 画面のデザインガイド

農場と大会モードの画面 (`publish_or_perish/web/`) の見た目と、部品の形を決める。
対象は、3D の畑の上に重ねる HUD (札、ボタン、窓、通知) と、3D の中に描く文字の色である。
値の一覧は [トークンの表](ui-tokens.md) に分けた。
画面の作りは [画面の作り直しの設計](web-architecture.md) を前提にしている。

評価は、2026-11-22 時点の画面のスクリーンショット 12 枚 (全体、マスの情報、配線図、お店、実績、説明、ログと点検、1000×700 の狭い画面、500×380 の小さい窓、大会モード、説明の中のターミナルの出力、ログの原文と訳) と、`web/src/farm/farm.css` に基づく。
見本は [ui-guide/components.html](ui-guide/components.html) に置いた。
この見本はブラウザで描いて確かめていないので、値の正は本文とトークンの表である。

## 前提

見た目の方向は今のまま保つ。
紙のような札、太い枠、押し込むボタン、空色の背景、達成を祝う演出である。
このガイドが提案する変更は、この方向の中での改善に限る。

部品は `web/packages/ui` にまとめ、画面はその部品だけで組む。
実装には Tailwind CSS 4、Base UI、tailwind-variants、Storybook を使う予定で、決まりはこれらで書ける形にした。
ただし、形と色の決まりそのものは CSS の値で書いてあり、道具が替わっても読める。

## 原則

### 「ゲームらしさ」が指すもの

このガイドでは、**ゲームらしさ** を次の四つの性質として扱う。

- **物として描く**：札には厚みがあり、ボタンは押すと沈み、お金はコインで、レベルはメダルで示す。HUD の部品を、畑の柵や看板と同じ世界の物に見せる
- **反応が返る**：ボタンを押したとき、service が返事をしたとき、お金が増えたときに、0.1 秒以内に画面のどこかが動く
- **進みが見える**：レベル、XP、ステージの帯、課題のメーターが、操作をしなくても常に見えている
- **達成を祝う**：課題、ステージ、レベル、実績の達成を、大きさの違う三段の演出で知らせる

状態を運ばない飾りは、ゲームらしさに数えない。
意味のないグラデーション、何も起きていないときの動き、文字の装飾がこれに当たる。
受講生の目は ROS の状態と課題の文を追っているので、状態を運ばない飾りは、読むものを増やすだけになる。

### 読む文は飾らない

課題の説明、点検、ガイドは教材の本文であり、受講生は入門者である。
ゲームらしさは札の枠、見出し、数字、ボタンで出し、本文には持ち込まない。

- 本文は `ink` の文字を `surface` の上に置く (比 14.53)。色の地の上に長い文を置かない
- 本文の書体は OS のゴシックにする。丸い書体は見出し、ボタン、数字に限る
- 本文の大きさは 13 px 以上、行の高さは 20 px 以上にする
- 色だけで意味を伝えない。エラー、注意、成功には、言葉かアイコンを必ず添える

### 畑を隠さない

受講生は、ターミナルでコマンドを打ち、その結果を畑で確かめる。
畑が見えていないと、打ったコマンドが効いたかを確かめられない。

- 画面の中央 (幅の 50%、高さの 60%) には、常に出ている札を置かない
- 畑を見ながら読むもの (課題、点検、説明) は、画面の端の札か、横の紙に出す
- 幕を引いて畑を隠す窓は、畑を見なくてよい用事 (お店、実績) に限る
- 札の地は 0.94 の半透明のままにし、畑とのつながりを残す。ただし、文字の下に 3D の文字が透けて読みにくくなる札 (ログ) は濃くする

### 三つがぶつかったときの順番

読みやすさ、畑が見えること、ゲームらしさの順に優先する。
たとえば点検のエラーは畑を隠してでも課題の札の上に出すが、エラーの札そのものを揺らしたり光らせたりはしない。

## 今の画面の評価

### 良いところ

次のものは、今の形を決まりとして残す。

- **札と畑の色が合っている**：札の生成り (`#fffcf3`) と枠 (`#e3d9bf`) は、3D の柵 (`#c99a5b`) や土と同じ暖色で、空色と草の上で浮かない
- **左上の札がゲームの顔になっている**：金のメダル、コイン、太い数字が並び、開いた瞬間にゲームだと分かる。XP のメーターと称号 (「見習い農家」) が、進みを言葉と量の両方で見せている
- **ボタンに厚みがある**：下に 4 px の厚みがあり、押すと 2 px 沈む。この押し心地は部品の基準にする
- **誰が動かしているかの色がそろっている**：自分のノードは緑 (小屋の屋根、名札、LED、「無人運転中」の Pill)、CLI は琥珀色で、3D と HUD が同じ色を使っている
- **配線図がターミナルと地続きになっている**：topic の名前を暗い地の等幅で出しているので、`ros2 topic list` の出力と同じものだと読める。点線が頻度に合わせて流れ、送り手がいない側は赤い破線になる
- **マスの情報が教材になっている**：座標と水分に加えて `data[2 * 8 + 3] = data[19]` という添字の式を出している。課題で必要になる計算を、畑の上で見せている
- **ログの原文と訳が見分けられる**：英語の原文は等幅、訳は一段小さく字下げしてあり、失敗は色が変わる
- **開いているのは今の課題だけ**：終わっていない最初の課題だけに説明とヒントを出し、ほかは題と報酬だけにしている
- **小さい窓が 1 行にまとまっている**：500×380 の窓では、課題の題、メーター、お金、運転の Pill だけを出す。点検のエラーがあれば課題より先に出し、枠を赤くする
- **祝う演出が跳ねる**：通知は弾んで落ち、帯は傾いて飛び出す。イージングの値は残す

### 改善するところ

スクリーンショットで確かめた問題を、効きの大きい順に並べる。

1. **点検が課題を押し出している**：エラーが 3 件あると、1366×820 の画面で課題が 1 行も見えない。点検はすべて開いた状態で縦に積まれ、札の高さを使い切っている。→ 点検は 1 件だけ開き、残りは題の 1 行に畳む (「点検の札」を参照)
2. **点検の直し方が部品になっていない**：点検の中のコマンドは、暗い地が付かず、コピーのボタンがブラウザの既定の見た目で出ている。`.hint` の見た目が課題の行 (`.m`) の中でしか効かないためである。長いコマンド (`<buildtool_depend>ament_cmake_auto</buildtool_depend>`) は札の右からはみ出し、1000 px の画面では途中で切れている。→ コードブロックを一つの部品にし、課題と点検で同じものを使う
3. **狭い画面でログが課題の札に重なる**：1000×700 では、ログが画面の幅いっぱいに広がり、課題の札の下の 2 行を隠している。→ ログの右の端を、課題の札の左の端までにする (「配置」を参照)
4. **窓の後ろが透けて読める**：説明の窓の後ろに、お金の「100」と課題の文が読める濃さで残っている。幕が 0.35、窓の地が 0.94 だからである。→ 窓の地を不透明にし、幕を 0.55 にする
5. **説明を開くと畑が見えなくなる**：説明は幅 860 px の窓で、畑のほぼ全体を隠す。説明は、コマンドを打ちながら読むものである。→ 説明は窓ではなく、右の横の紙に出す
6. **薄い文字が読めない**：次の文字は、地との比が 4.5 に届いていない

   | 場所 | 今の色 | 比 |
   |---|---|---|
   | 買えない品の値段 (不透明度 0.45) | `#1f2a1f` の 0.45 (地と混ざって `#9a9e94`) | 2.66 |
   | まだ取っていない実績の題 | `#b5ab90` | 2.13 |
   | 準備中のステージ | `#a39a80` | 2.73 |
   | 「停止中」の Pill | `#888` と `#eee` | 3.06 |
   | 実績の数のバッジ (金の上の白) | `#fff` と `#e8a923` | 2.07 |
   | 「!」のバッジ (赤の上の白) | `#fff` と `#e05244` | 3.85 |
   | マスの情報の式、点検の「開く」 | `#3b82c4` | 3.95 |
   | 配線図の「送り手なし」 | `#e05244` | 3.85 |
   | ログの時刻の色 | `#7b9a7b` | 3.50 から 4.14 |

   → [トークンの表](ui-tokens.md) の `ink-faint`、`on-gold`、`danger-strong`、`info-ink`、`term-sub` に替える
7. **文字の大きさが 15 通りある**：10.5、11、11.5、12、12.5、13 px のように 0.5 px 刻みの値が並び、段の違いが目で分からない。→ 9 段にする
8. **買えない理由が分からない**：お店の買えない品は、ボタンが薄くなるだけである。→ 値段は読める濃さで出し、「あと 50 G」を添える
9. **パスが長いまま折り返されている**：点検のファイルの場所が、11 px の補足の色で 4 行に折り返される。→ 末尾の 3 階層だけを出し、頭を `…/` で省く
10. **ログに同じ行が並ぶ**：「作物の時間を 2 倍速にした」のような行が 6 行続き、8 行の枠を使い切る。→ 続けて同じ文が出たら 1 行にまとめ、「×6」を添える
11. **失敗した英語の文が切れる**：ログは 1 行で切って `…` にする。英語の失敗の文には、次に何をすればよいかを含める決まりがある。助言は文の後ろに来ることが多く、切れるのはその部分になりやすい。→ 失敗の行は 3 行まで折り返す
12. **「接続中」が光り続けている**：接続の Pill が、何も起きていなくても 1.6 秒ごとに光る。「無人運転中」と同じ見た目を使っているためである。→ 光らせるのは「無人運転中」だけにする
13. **右下のボタンが同じ重さで並ぶ**：早送り、配線、お店、実績、音が、同じ形の文字だけのボタンである。「音: 切」は押せるボタンなのか状態の表示なのかが分かりにくい。→ アイコンを付け、早送りと音は押し込んだままになる切り替えのボタンにする
14. **札の枠が見えにくい**：決まっている方向は「太い枠」だが、今の枠の色 (`#e3d9bf`) は札の地との比が 1.37 で、草の上ではぼかした影だけが札の輪郭になっている。→ 枠を `edge` (`#c9bc98`) にし、下に 3 px の厚みを付けて、ボタンと同じ「紙の板」にする
15. **キーボードで使えない部品がある**：ステージの題 (畳む操作) は `h2` のクリック、点検の「開く」は `href` のない `a` で、Tab で届かない。窓は Esc で閉じず、フォーカスが窓の外へ出る。フォーカスの輪は決めていない。→ 操作の部品を Base UI に任せ、輪を決める (「使いやすさ」を参照)
16. **コピーのボタンが文字に重なる**：課題のヒントは右に 34 px しか空けておらず、「コピー」のボタンがコマンドの端に重なる。押したあとの「済」は元に戻らない。→ 右を 64 px 空け、「済」は 1.5 秒で戻す
17. **大会モードが別の見た目になっている**：フィールドの緑 (彩度の高い純色) が農場の草と合わず、状態の欄には `-` が 2 行出ている。キーの札には厚みがない。→ 同じトークンと部品で組み直す。フィールドの色は 3D の側の話なので、このガイドでは札だけを扱う
18. **3D の座標の文字が草に沈む**：`x=0` などの文字 (`#4d5a3c`) は、草との比が 3.23 である。→ `#2f3a26` (比 5.23) にする

## 見た目の決まり

値の一覧は [トークンの表](ui-tokens.md) にある。
ここでは、値をどう使い分けるかを書く。

### 色

色は役割の名前で呼び、部品の中に色の値を直接書かない。

- **地は三層**：畑の上の札は `surface-hud` (半透明)、窓と横の紙は `surface` (不透明)、札の中で一段沈める面は `surface-sunken` を使う
- **文字は三段**：本文は `ink`、補足は `ink-sub`、今は使えないものは `ink-faint`。三つとも、どの地の上でも比 4.5 以上になる値にしてある (`ink-faint` は `track` の上だけ 4.20 なので、`track` の上には置かない)
- **役割の色は塗り、淡い地、文字の三つ組**：たとえばエラーは、左の帯が `danger`、札の地が `danger-soft`、強調する文字が `danger-ink` である。塗りの色を文字に使わない (`danger` の文字は `surface` との比が 3.75 しかない)
- **暗い地はターミナル**：`term` の地と等幅の文字は、「ターミナルに出るもの、ターミナルに打つもの」だけに使う。飾りとして暗い札を作らない
- **金は報酬と進み**：お金、報酬、レベル、課題のメーター、今のステージに使う。注意を引くためだけに金を使わない

### 書体

書体は三つに分ける。

- **本文 (`font-sans`)**：OS のゴシックを使い、同梱しない。受講生の環境は Ubuntu (Noto Sans CJK JP) か、WSL でブラウザが Windows の側 (Yu Gothic UI、Meiryo) にある場合が多い
- **見出しと数字 (`font-display`)**：丸い書体の M PLUS Rounded 1c の Bold を 1 本だけ同梱する。札と窓の題、ボタン、Pill、お金とレベルの数字、通知の題、帯に使う
- **コード (`font-mono`)**：JetBrains Mono の Regular と Bold を同梱する。コマンド、コード、topic の名前、ターミナルの英語の原文に使う

丸い書体を本文にまで使わない理由は三つある。
一つ目は、ガイドの本文が任意の文章で、同梱する字の範囲 (JIS 第 1 水準) から外れた漢字だけが OS のゴシックで出て、文の中で字の形が混ざることである。
二つ目は、本文用にもう 1 本の太さ (Regular か Medium) が要り、配るファイルが増えることである。
三つ目は、ゲームらしさは見出し、ボタン、数字で足りており、本文は読み慣れた書体のほうが読みやすいことである。

等幅を同梱するのは、今は OS によって書体が変わり (`Cascadia Code`、`DejaVu Sans Mono`、`Noto Sans Mono`)、ログ、コードブロック、将来のエディタで字の幅がそろわないからである。
等幅の合字 (`->` や `!=` を一つの記号にまとめる機能) は切る。
入門者が、打つ文字と画面の文字を一対一で見比べられるようにするためである。

数字は `font-variant-numeric: tabular-nums` を付け、お金や XP が変わっても幅が動かないようにする。

3D の中の文字は、canvas に `sans-serif` で描いている。
これを `font-display` にそろえる。
canvas は読み込みの済んでいない書体では描けないので、`document.fonts.load()` を待ってから描く。

同梱する書体は、どちらも SIL Open Font License 1.1 である。
サブセットにしたあとのファイルの大きさは測っていない。

### 文字の大きさ

大きさは 9 段にする (11、12、13、14、16、18、22、28、40 px)。

- 日本語の文は 12 px 以上にする。11 px は、XP の数や Hz のような英数字だけの補足に限る
- 畑の上の札の本文は 13 px、窓の本文は 14 px にする
- 一つの札の中で使う大きさは 3 段までにする
- 狭い画面と小さい窓でも、段を一つ下げるだけにする。12 px より小さくしない

### 角丸、枠、厚み

札とボタンは、2 px の枠と、下の厚みと、角丸の三つで「紙の板」に見せる。

- 枠は 2 px で、色は `edge`。札の中の区切りは 1 px の破線で、色は `line`
- 厚みは、ぼかさない影 (`0 4px 0 lip`) で描く。ボタンは 4 px、札は 3 px、小さいボタンは 2 px
- 角丸は、外側の部品ほど大きくする。札と窓が 16 px、ボタンと札の中の札が 12 px、コードブロックと小さい部品が 8 px である。入れ子にするときは、内側を一段小さくする
- 厚みのある札を、厚みのある札の中に入れない。中に置く札は、厚みも影もない `surface-sunken` の面にする

### 余白と重なり

余白は 4 px を 1 単位にし、札の内側は 16 px、画面の端から札までは 16 px を基準にする。
重なりの順番は、畑、札、浮かぶ文字、横の紙、窓、ツールチップとメニュー、帯、通知、接続待ちの順である。
ツールチップとメニューを窓より上にしたのは、窓の中の部品からも開くからである。

## 意味の色

「誰が動かしているか」は、このゲームでいちばん大事な状態である。
課題の多くは「CLI で動かす」から「自分のノードで動かす」への移り変わりを見ており、受講生はそれを色で追う。
そこで、次の対応を HUD と 3D の両方で守る。

| 意味 | 色 | HUD での現れ方 | 3D での現れ方 |
|---|---|---|---|
| 自分のノード | 緑 (`src-player`) | 「無人運転中」の Pill、配線図のノードの枠、小さい窓の「無人」 | 小屋の屋根 `#4caf50`、名札の地、ロボットの LED `#5bf06a` |
| CLI | 琥珀色 (`src-cli`) | 「CLI で操作中」の Pill、配線図の `CLI (...)` の枠 | CLI の小屋の屋根 `#f0a020`、名札の地、LED `#ffb43a` |
| 農場 (`farm_node`) | 青 (`src-farm`) | 配線図の `farm` の枠 | 農場が出す topic の粒 `#5ab8ff` |
| 自分のノードと CLI がぶつかっている | 赤 (`src-mixed`) | 配線図の警告の行 | LED `#ff5a4a` |
| 道具、または誰もいない | 生成りと `ink-faint` | 配線図の「まだ誰も見ていない」 | LED `#999999` |

HUD と 3D で値が少し違うのは、3D の LED と粒が自分で光る材質で、明るい値にしないと草の上で見えないからである。
色相は同じにそろえる。

### 色だけに頼らない

緑と赤、琥珀色と金は、色覚によっては見分けにくい。
そこで、色には必ず形か言葉を添える。

- 自分のノードはノードの名前 (`/my_patrol`) を、CLI は `CLI` の文字を必ず出す。色の点だけで示さない
- 配線図の「送り手なし」は、赤に加えて破線の枠にする (今のまま)
- 点検の札は、色に加えて「エラー:」「注意:」の言葉とアイコンを付ける

### 琥珀色と金の使い分け

琥珀色 (`#f0a020`) と金 (`#e8a923`) は色相が近く、色では見分けられない。
この二つは、現れる形を分けて区別する。

- 金は、量を表す形にだけ使う (メーターの塗り、コイン、メダル、数のバッジ、ステージの帯)
- 琥珀色は、状態を表す形にだけ使う (Pill、ノードの枠、小屋の屋根、点検の札の左の帯)
- 琥珀色の Pill には `CLI` か「注意」の言葉が入る。金の部品に言葉は入らず、数字が入る

CLI と注意の両方が琥珀色なのは、今の画面から引き継いだ。
「CLI で動かしている」は、このゲームでは「まだ自動になっていない」という軽い注意でもあるので、意味は遠くない。

### 3D の粒の色

今の 3D は、topic の粒を topic の種類で塗り分けている (`cmd_vel` は琥珀色、`pose` と `tank` は青、`field` は緑、`money` は金、`board` は桃色)。
この塗り分けは、上の表とぶつかる。
自分のノードが出した `cmd_vel` の粒が琥珀色 (CLI の色) で飛び、農場が出した `field` の粒が緑 (自分のノードの色) で飛ぶからである。

粒の色は送り手の色にそろえる案を勧める。
自分のノードの小屋から出る粒は緑、CLI の小屋から出る粒は琥珀色、農場から届く粒は青にする。
topic の種類は、粒の行き先 (ロボット、畑、看板) で分かる。
この変更は 3D の振る舞いを変えるので、採るかどうかは「決めていないこと」に挙げた。

## 部品の仕様

寸法は広い画面のものである。
狭い画面と小さい窓での変え方は「配置」に書く。
状態の名前は、Base UI が付ける `data-*` 属性と、CSS の疑似クラスのどちらで書いてもよい。

### 札

畑の上に常に出ている、情報のまとまりである。

- **形**：地は `surface-hud`、枠は 2 px の `edge`、角丸 16 px、内側 16 px、影は `shadow-card` (3 px の厚みと、ぼかした影)
- **題**：18 px の `font-display`。題の右に、畳むボタンや数のバッジを置ける
- **中の区切り**：1 px の破線 (`line`)
- **変種**：
  - `hud`：上の形。四隅の札
  - `solid`：地を `surface` にしたもの。窓、横の紙、通知、ツールチップの土台
  - `sunken`：地は `surface-sunken`、枠は 2 px の `line`、角丸 12 px、厚みと影なし。札の中の札 (実績の 1 枚、折りたたみ)
  - `danger`：枠を `danger` にしたもの。小さい窓の 1 行で、点検のエラーがあるとき
- **使いどころ**：一つの札には一つの話題だけを入れる。札を増やす前に、既にある札の中の行にできないかを考える

### ボタン

| 変種 | 地 | 文字 | 枠 | 厚み | 使いどころ |
|---|---|---|---|---|---|
| 主 (`primary`) | `gold` | `on-gold` | 2 px の `gold-ink` | 4 px の `gold-ink` | 一つの札か窓に 1 個まで。買う、次のステージへ進む |
| 副 (`secondary`) | `surface` | `ink` | 2 px の `edge` | 4 px の `lip` | 右下のボタン列、説明を読む、窓を開く |
| 暗い地の上 (`onTerm`) | `term-raised` | `#ffffff` (比 7.27) | なし | なし | コードブロックのコピー |
| リンク (`link`) | なし | `info-ink`、下線 | なし | なし | 点検の「開く」、文中のリンク |

大きさは二つある。

- **中 (`md`)**：高さ 40 px (面 36 px と厚み 4 px)、左右の内側 16 px、角丸 12 px、文字は 14 px の `font-display`
- **小 (`sm`)**：高さ 30 px (面 28 px と厚み 2 px)、左右の内側 12 px、角丸 8 px、文字は 12 px の `font-display`

アイコンだけのボタンは、中が 40×40 px、小が 30×30 px の正方形にし、`aria-label` とツールチップを付ける。

状態は次のとおりである。

| 状態 | 見た目 |
|---|---|
| 通常 | 上の表のとおり |
| ホバー | 副は地を `#ffffff` に、主は `gold-bright` にする。位置は動かさない |
| 押し込み中 | 2 px 下げ、厚みを 2 px にする (80 ms)。面と厚みの合計が変わらないので、まわりは動かない |
| 押し込んだまま (切り替えが入) | 押し込み中の位置のまま、地を `gold-soft`、枠を `gold-ink` にする。`aria-pressed="true"` |
| 押せない | 地は `surface-sunken`、文字は `ink-faint` (比 4.72)、枠は `line`、厚みなし、2 px 下げた位置。不透明度は下げない |
| フォーカス | 部品の外側 2 px に、3 px の `info-ink` の輪 (「使いやすさ」を参照) |
| 処理中 | 文字を残したまま、左に回る印を出す。押せない状態にはせず、二度押しだけを無視する |

押せないボタンには、押せない理由を添える。
お店では、値段のボタンの下に「あと 50 G」を 12 px の `ink-sub` で出す。
押せないボタンも Tab で届くようにし (`aria-disabled`)、理由を読み上げられるようにする。

切り替えのボタンは二種類ある。
音は、一つのボタンの入と切である (アイコンがスピーカーと、斜線の入ったスピーカーに替わる)。
早送りは、`×1`、`×2`、`×4` の三つが並んだ組で、選んだ一つが押し込んだままになる。
今の「押すたびに次の値に替わる」形は、今の値と押した結果が同じ場所に出るので、どれを選んでいるかが分かりにくい。

### Pill

状態を一語で示す、角の丸い札である。
押せない。
押せるものはボタンの小にする。

- **形**：高さ 20 px、左右の内側 10 px、角丸は `radius-full`、文字は 12 px の `font-display`。左に 6 px の丸い点を置ける
- **色**：

  | 色調 | 地 | 文字 | 比 | 使いどころ |
  |---|---|---|---|---|
  | `player` | `success-soft` | `success-ink` | 4.62 | 接続中、無人運転中 |
  | `cli` | `cli-soft` | `warning-ink` | 5.18 | CLI で操作中、動作中 |
  | `farm` | `info-soft` | `info-ink` | 7.39 | 農場のノード |
  | `danger` | `danger-soft` | `danger-ink` | 6.31 | 切断、配線の警告 |
  | `neutral` | `neutral-soft` | `ink-sub` | 4.54 | 停止中、未接続 |
  | `gold` | `gold` | `on-gold` | 6.13 | 数のバッジ (実績 2/12) |
  | `alert` | `danger-strong` | `#ffffff` | 5.26 | 「!」のバッジ |

- **光る (`live`)**：外側に緑の輪が 1.6 秒の周期で広がる。「無人運転中」にだけ使う。画面の中で光り続ける部品は、同時に一つまでにする

### メーター

量を横の棒で示す。

- **形**：溝は `track`、外枠は 1 px の `control` (`track` との比 3.26)、角丸 4 px。高さは、課題が 10 px、XP が 14 px (外枠 2 px)、小さい窓が 6 px
- **塗り**：
  - `gold`：課題の進み具合
  - `xp`：`success-bright` から `success-deep` へのグラデーション。XP
  - `water`：`info`。ロボットのタンク (今は文字だけなので、足すときに使う)
- **数**：メーターの下か右に、`3 / 10 マス` の形で数を必ず添える (12 px の `ink-sub`)。塗りと溝の比は 1.56 (金) で 3 に届かないので、量を棒だけで伝えない
- **動き**：値が変わったら 400 ms で幅を変える (XP は 600 ms)
- **満ちたとき**：課題のメーターは、満ちたら塗りを `success` に替える
- **実装**：進み具合は Base UI の Progress、タンクのような残りの量は Meter で作る

ステージの帯は、メーターの仲間である。
ステージの数だけ節を並べ、済んだ節は `success`、今の節は `gold`、まだの節は `track` にする。
節は高さ 8 px、あいだ 4 px、外枠 1 px の `control` で、右に `1 / 12` を 11 px で添える。

### 窓

幕を引いて、画面の中央に出す札である。

- **形**：`solid` の札、角丸 16 px、内側 20 px、影は `shadow-overlay`。幅は中が 560 px、大が 860 px で、どちらも画面の幅の 92% まで。高さは画面の 80% まで
- **頭**：左に題 (18 px の `font-display`)、右に閉じるボタン (アイコンだけの小、`aria-label` は「閉じる」)。中身を送っても、頭は上に残す
- **幕**：`scrim` (`rgb(30 40 30 / 0.55)`)
- **開閉**：開くときは 0.96 倍から 1 倍へ、240 ms でフェードとともに出す。閉じるときは 160 ms のフェードだけ
- **操作**：Esc、幕のクリック、閉じるボタンで閉じる。開いているあいだ、フォーカスは窓の中を回る。閉じたら、開いたボタンにフォーカスを戻す
- **使いどころ**：お店、実績、配線図。一度に開く窓は一つにし、窓の上に窓を重ねない
- **実装**：Base UI の Dialog

横の紙は、窓の仲間で、幕を引かない。

- **形**：`solid` の札を画面の右の端に出す。幅 480 px (画面の幅から 32 px を引いた幅まで)、上下は画面の端から 16 px
- **開閉**：右から 24 px の位置からすべり込む (240 ms)。開いているあいだ、課題の札は隠す
- **頭**：左に「課題にもどる」のボタン、中央に題、右に閉じるボタン
- **操作**：幕がないので、畑もターミナルも、開いたまま使える。Esc で閉じる
- **使いどころ**：説明。VSCode の中では、今と同じくエディタの横のプレビューで開くので、横の紙は使わない

### ツールチップ

- **形**：`solid` の札、角丸 12 px、内側は上下 8 px と左右 12 px、文字は 12 px、影は `shadow-pop`、幅は 280 px まで
- **出方**：アイコンだけのボタンでは、ホバーかフォーカスから 400 ms で出す。マスの情報は、マウスの右下 (右へ 16 px、下へ 12 px) に遅れなしで出す
- **端の扱い**：画面の端で切れるときは、反対側に出す (今のマスの情報は、右の端で画面からはみ出す)
- **中身**：操作する部品を入れない。式や topic の名前は、等幅の `info-ink` で出す
- **実装**：ボタンのものは Base UI の Tooltip。マスの情報は 3D のマウスの位置に合わせるので、同じ見た目の札を自前で置く

### 通知

- **形**：`solid` の札、角丸 16 px、内側は上下 12 px と左右 24 px、枠は 2 px、影は `shadow-pop`。左に 24 px のアイコン、右に題 (16 px の `font-display`) と本文 (13 px の `ink-sub`)
- **種類**：

  | 種類 | 枠 | アイコン |
  |---|---|---|
  | 課題の達成 | `gold` | コイン |
  | ステージの達成 | `success` | 旗 |
  | 実績 | `special` | メダル |

  今は枠の色だけで種類を分けているので、アイコンを足す
- **場所**：画面の上の中央に、8 px のあいだで縦に積む。同時に出すのは 3 件まで
- **長さ**：4200 ms で消える。ホバーかフォーカスのあいだは消さない
- **実装**：Base UI の Toast。読み上げは `role="status"`

### 帯

レベルアップとステージの達成を、画面の中央で知らせる。

- **形**：地は `gold-bright` から `gold` へのグラデーション、文字は `on-gold`、枠は 2 px の `gold-ink`、角丸 24 px、内側は上下 24 px と左右 64 px、影は `shadow-overlay`。上に本文 (16 px)、下に題 (40 px の `font-display`)
- **動き**：0.3 倍、−8 度の傾きから、700 ms で飛び出す。2600 ms で消える
- **操作**：マウスもキーも受けない (`pointer-events: none`)。畑の操作を止めない
- **使いどころ**：レベルアップとステージの達成だけ。帯が出ているあいだに次の帯が来たら、順に出す

今の帯のグラデーションは `#ffe27a` から `#f0a020` (琥珀色) である。
琥珀色は CLI と注意の色なので、帯は金 (`#ffd45a` から `#e8a923`) にそろえる。

### タブ

- **形**：高さ 36 px、左右の内側 16 px、上の角だけ 12 px の角丸、文字は 14 px の `font-display`。選んだタブは、地が下の面と同じ色で、上と左右に 2 px の `edge` の枠が付き、下の面とつながる。選んでいないタブは、地が `track`、文字が `ink` (比 11.25)
- **状態**：ホバーで地を `surface-sunken` にする。フォーカスの輪はボタンと同じ
- **操作**：左右の矢印で隣のタブへ移り、Tab で中身へ入る
- **使いどころ**：同じ場所で中身を切り替えるとき。今の画面には使う場所がなく、将来のエディタのファイルの切り替えで使う
- **実装**：Base UI の Tabs

### メニュー

- **形**：`solid` の札、角丸 12 px、内側 4 px、影は `shadow-pop`。項目は高さ 32 px、左右の内側 12 px、角丸 8 px、文字は 13 px
- **状態**：指している項目は地を `gold-soft` にする。選んである項目は左にチェックを出す。押せない項目は `ink-faint`
- **操作**：上下の矢印で移り、Enter で選び、Esc で閉じる
- **使いどころ**：小さい窓の 1 行の右の端に置く「…」のボタン (お店、配線、実績、音、早送りを出す)、言語の切り替え
- **実装**：Base UI の Menu

### 入力欄

- **形**：高さ 36 px、地は `#ffffff`、枠は 2 px の `control`、角丸 8 px、左右の内側 12 px、文字は 14 px。コマンドや topic の名前を入れる欄は等幅にする
- **見出し**：欄の上に 12 px の `ink-sub` で置く。プレースホルダーを見出しの代わりにしない
- **状態**：フォーカスで輪を出す。誤りがあるときは枠を `danger` にし、欄の下に 12 px の `danger-ink` で理由を出す。押せないときは地を `surface-sunken` にする
- **使いどころ**：今の画面には無い。ログの絞り込みや、将来のエディタのファイル名で使う
- **実装**：Base UI の Field と Input

### コードブロック

受講生がターミナルに打つコマンドか、ファイルに書くコードを出す。

- **形**：地は `term`、文字は `term-text` の等幅、角丸 8 px、内側は上下 8 px と左右 12 px、行の高さは 1.5 倍。文字は、窓の中で 13 px、畑の上の札の中で 12 px
- **コピー**：右上に `onTerm` の小のボタンを置く。文字がボタンの下に入らないよう、1 行目の右を 64 px 空ける。押すと「済」に替わり、1.5 秒で「コピー」に戻る
- **長い行**：
  - 畑の上の札の中 (課題のヒント、点検の直し方)：どこででも折り返す (`overflow-wrap: anywhere`)。横に送らせない。札が狭く、コマンドの全体が見えていることのほうが大事だからである
  - 窓と横の紙の中：折り返さず、横に送る。コードは字下げと改行の位置が意味を持つからである
- **中身**：一つのブロックには、そのまま貼って動くものだけを入れる。プロンプトの `$` は入れない
- **文中のコード**：地は `surface-sunken`、角丸 4 px、左右の内側 4 px、まわりの文より一段小さい等幅

### ターミナルの出力

プログラムがターミナルに出す文を、英語の原文と訳の組で出す。
コードブロックと地は同じだが、コピーのボタンは付けない (打つものではないため)。

- **原文**：`term` の地に、`term-text` の等幅で出す。ターミナルに出るとおりに出し、省かない
- **訳**：原文のすぐ下に、あいだを空けずにつなげる。地は `surface-sunken`、文字は 12 px の `ink-sub` で、OS のゴシックにする (等幅にしない)。頭に「訳」の小さい札 (`neutral` の Pill) を置く。下の角だけ 8 px の角丸にし、原文の箱と一つの部品に見せる
- **英語の画面**：訳の段を出さない

訳を暗い地の中に入れないのは、暗い地の等幅が「ターミナルに出るそのまま」を意味するからである。
訳はターミナルには出ない。
今の説明は、訳を引用の形 (左に線のある段) で、原文から 8 px 離して出している。
これを原文につなげ、組であることを形で示す。

### ログの行

左下のログは、畑の上で使うターミナルの出力である。
全体が暗い地 (`term-hud`) なので、訳は地ではなく、書体と字下げで分ける。

- **札**：地は `term-hud`、角丸 12 px、内側は上下 8 px と左右 12 px、幅は 560 px まで。枠と厚みは付けない (紙の札ではなく、画面に開いたターミナルとして見せる)
- **行の種類**：

  | 種類 | 1 行目 | 2 行目 |
  |---|---|---|
  | ターミナルにも出た結果 (成功) | 何への返事か (`service /bot1/water`) を `term-sub` の等幅、`→`、原文を `term-text` の等幅 | 訳。12 px の `term-sub`、OS のゴシック、左を 16 px 下げる |
  | ターミナルにも出た結果 (失敗) | 左に × の印。原文は `term-danger` | 訳。`term-danger-sub` |
  | 画面にだけ出る知らせ | 13 px の `term-text`、OS のゴシック | なし |
  | 点検の知らせ | 頭に「点検」の札 (`danger` の Pill)、文は `term-danger` | なし |

- **組のまとまり**：原文と訳のあいだは 0 px、次の行とのあいだは 4 px 空ける
- **長い行**：成功の行は 1 行で切り、`…` を付ける。失敗の行は、原文も訳も 3 行まで折り返す
- **くり返し**：直前と同じ文が続いたら行を足さず、末尾に `×6` を `term-sub` で添える
- **行の数**：広い画面で 8 行、狭い画面で 3 行。新しい行は下に足す
- **読み上げ**：`role="log"` を付ける

### 点検の札

受講生のワークスペースの間違いを、課題の札のいちばん上に出す。

- **まとめの行**：点検が 1 件でもあれば、「点検」の見出しと、件数の Pill (エラー 3、注意 1) を 1 行で出す
- **1 件の形**：角丸 12 px、左に 4 px の帯、内側は上下 8 px と左右 12 px、厚みと影なし

  | 段階 | 帯 | 地 | アイコン | 題の頭 |
  |---|---|---|---|---|
  | エラー | `danger` | `danger-soft` | 丸に × | エラー: |
  | 注意 | `warning` | `warning-soft` | 三角に ! | 注意: |
  | 情報 | `info` | `info-soft` | 丸に i | なし |

- **中身**：上から、題 (13 px の太字)、ファイルの場所、説明 (13 px、行の高さ 20 px)、直し方のコードブロック
- **ファイルの場所**：等幅の 12 px、`ink-sub`。ホームは `~` に置き換え、末尾の 3 階層だけを出して頭を `…/` で省く (`…/tutorial_nodes/src/patrol.cpp:3`)。全体は `title` 属性に入れる。VSCode の中では、右に「開く」のリンクのボタンを置く
- **畳み方**：エラー、注意、情報の順に並べ、いちばん上の 1 件だけを開く。残りは題の 1 行に畳み、押すと開く。開いているのは常に 1 件にする
- **高さ**：点検の全体は、課題の札の高さの半分までにする。越える分は、点検の中で送る
- **動き**：新しい点検が出たときも、札は揺らさない。まとめの行の Pill の数字だけを、お金と同じ跳ね (400 ms) で 1 回動かす
- **実装**：Base UI の Accordion

### 課題の行

- **チェックの箱**：20×20 px、枠は 2 px の `control`、角丸 8 px。済んだら地を `success` にし、`ink` のチェックを入れる (白のチェックは `success` との比が 2.78 しかない。`ink` は 5.36)
- **題**：14 px の太字。済んだ課題は `ink-sub` にする。今の取り消し線は付けない (線が日本語の字画に重なり、読みにくくなる)
- **報酬**：右の端に、14 px のコインと `+50 G` を `gold-ink` の `font-display` で出す
- **メーター**：目標が 2 以上の課題に出す
- **開いた行**：説明 (13 px)、ヒントのコードブロック、「説明を読む」のボタン (副の小) を出す。今のボタンの文 (「説明を読む (書くものと, うまくいかないときの直し方)」) は 2 行に折り返されるので、ボタンは「説明を読む」だけにし、括弧の中は説明の側に書く

### 配線図の部品

- **ノードの札**：等幅の 12 px、内側は上下 2 px と左右 8 px、角丸 8 px、地は `surface`、枠は 2 px で意味の色。「送り手なし」「受け手なし」は `danger` の破線の枠に `danger-ink` の文字、「まだ誰も見ていない」は `edge` の枠に `ink-faint` の文字
- **topic の札**：地は `term`、角丸は `radius-full`、1 行目に topic の名前 (`term-text` の等幅 12 px)、2 行目に型と頻度 (`term-sub` の 11 px)
- **線**：2.5 px の破線、色は `control`。頻度に合わせて流す。止まっている線は `danger` にし、流さない

### キーの札

大会モードの操作の表で、キーを示す。

- **形**：24×24 px 以上、地は `#ffffff`、枠は 2 px の `edge`、厚みは 2 px、角丸 4 px、文字は等幅の 12 px の太字
- **使いどころ**：キーボードのキーを指すときだけに使う。コードには文中のコードを使う

### アイコン

- 24×24 px の枠に、太さ 2 px の線で描いた SVG を同梱する。線の端と角は丸める
- 色は `currentColor` にし、文字の色に合わせる
- 絵文字と、アイコンの書体は使わない (OS によって絵が変わり、CDN から読む形のものが多いため)
- アイコンだけで意味を伝えない。ボタンには文字か `aria-label` を付ける

### 小さい窓 (幅 560 px 未満か、高さ 420 px 未満)

- **「…」のボタン**：メニューを開き、課題の全体、お店、配線図、実績、音、早送りへ行けるようにする。今は、小さい窓からこれらに届かない

### 区切りを何の幅で決めるか

今の区切りは、ブラウザの窓の幅と高さで決めている。
将来、画面の中にエディタを並べると、窓は広いのに畑の領域は狭い、という場合が出る。
そのときに同じ畳み方を使えるよう、区切りは「HUD を置く領域の幅と高さ」で決める形にしておく (CSS のコンテナクエリ)。
今は、HUD の領域が窓の全体なので、結果は変わらない。

## 動き

### 長さとイージング

| 場面 | 長さ | イージング |
|---|---|---|
| ボタンの押し込み | 80 ms | `ease-out` |
| ホバー、フォーカス、ツールチップ | 160 ms | `ease-out` |
| 窓、横の紙、メニュー、折りたたみ | 240 ms | `ease-out` |
| メーター、お金の跳ね | 400 ms | メーターは `ease-out`、跳ねは `ease-bounce` |
| XP のメーター | 600 ms | `ease-out` |
| 通知が落ちてくる | 450 ms | `ease-bounce` |
| 帯が飛び出す | 700 ms | `ease-pop` |

受講生の操作への反応は 240 ms 以内に終える。
それより長い動きは、ゲームの側から知らせる演出 (メーター、通知、帯) に限る。
閉じる動きは、開く動きより短くする (160 ms のフェード)。

### 祝う演出の強さ

演出は三段に分け、出来事の大きさに合わせる。

| 段 | 出来事 | HUD | 3D | 音 |
|---|---|---|---|---|
| 小 | 収穫でお金が増えた、水をやった | お金の数字が 1.18 倍に跳ねる。畑から `+70 G` が浮かぶ | 水や土の粒 | 短い音 |
| 中 | 課題の達成、実績 | 通知。課題の行のチェックが入り、メーターが緑になる | 光の粒 | 達成の音 |
| 大 | ステージの達成、レベルアップ | 帯。XP のメーターが満ちてから空に戻る | 紙吹雪 | ファンファーレ |

- 大の演出は、続けて出さない。帯は順に出し、紙吹雪は帯 1 回につき 1 回にする
- 失敗を演出で責めない。失敗は、ログの赤い行と、畑から浮かぶ短い言葉 (「ゴツン」) までにする
- 何も起きていないときに動いているものは、「無人運転中」の Pill の光と、配線図の線の流れだけにする

### 動きを減らす設定

OS の「動きを減らす」設定 (`prefers-reduced-motion: reduce`) が入っているときは、次のようにする。

- 位置、大きさ、傾きを変える動き (通知の落下、帯の飛び出し、お金の跳ね、窓の拡大、横の紙のすべり込み) をやめ、160 ms のフェードにする
- くり返す動き (Pill の光、配線図の線の流れ) を止める。配線図は、頻度を数字でも出しているので、流れが止まっても情報は欠けない
- メーターの幅の変化は残す (量の変化そのものを示しているため)
- 3D の紙吹雪と粒を出さない。ロボットの動きと作物の成長は、状態そのものなので残す
- 浮かぶ文字は、上へ動かさず、その場に出して消す

通知と帯が出ている長さは変えない。
3D の側は CSS を読まないので、`matchMedia('(prefers-reduced-motion: reduce)')` を自分で見る。

## 文言の見せ方

### 英語の原文と訳

ターミナルに出る文は英語で、画面はその下に訳を添える。
見せ方の決まりは三つである。

- **原文は等幅、訳はゴシック**：等幅で出ているものは、ターミナルに出るとおりの文字である。訳を等幅にしない
- **原文が先、訳が後**：訳は、原文のすぐ下に、一段小さく、補足の色で出す。順番を入れ替えたり、訳だけを出したりしない。受講生がターミナルで見るのは原文だからである
- **組は離さない**：原文と訳のあいだには、ほかの行や余白を入れない

場所ごとの形は、「ターミナルの出力」(説明の中) と「ログの行」(畑の上) に書いた。
画面の言語が英語のときは、訳を出さない。

ROS の用語 (topic、service、node、publish、subscribe) は、訳の中でも英語のまま書く。
受講生がコマンドや文書で目にする綴りと同じにするためである。

### 長い英語の文が入ったとき

日本語の文は、どこで折り返しても読める。
英語の文と、パスやコマンドは、折り返し方を決めておかないと札からはみ出す。

| 中身 | 折り返し方 | 理由 |
|---|---|---|
| 英語の文 (原文、英語の画面の本文) | 単語のあいだで折り返す。1 語が行に入らないときだけ、語の中で折る (`overflow-wrap: break-word`) | 語の途中で切ると読めない |
| コマンド (畑の上の札の中) | どこででも折り返す (`overflow-wrap: anywhere`) | 全体が見えていることを優先する |
| コード (窓の中) | 折り返さず、横に送る | 字下げと改行が意味を持つ |
| パス | 頭を `…/` で省き、末尾を残す。それでも入らなければ `/` の後ろで折る | ファイルの名前と行の番号がいちばん大事 |
| topic の名前、ノードの名前 | 折り返さない。入らなければ末尾を `…` にし、全体をツールチップで出す | 名前の途中に改行が入ると、別の名前に見える |
| ボタン、Pill、タブの文 | 折り返さない。入らない訳は、訳を短くする | 部品の高さを変えない |
| 題 (課題、ステージ、窓) | 2 行まで折り返す | 英語は日本語の 1.5 倍から 2 倍の幅になる |

今の `farm.css` は、パスとコマンドに `word-break: break-all` を使っている。
これは日本語の文にも効き、禁則 (行の頭に句読点を置かない) を崩すので、上の表の指定に替える。

部品の幅は、文の長さで決めない。
英語にしたときにボタン列が画面からはみ出さないよう、ボタンの文は 6 字 (英語で 12 字) までにする。
Storybook には、すべての部品に「長い英語の文を入れた見本」を置き、崩れ方を目で確かめる。

### 文の書き方

- 句読点は、画面の文とガイドで同じにする。今は、課題と点検の文が半角のカンマ (「使っているが, 」) で、ガイドの本文が読点 (「、」) である
- 数字と単位のあいだは半角の空白を入れる (`2 m`、`10 回`)。今の文のとおりである
- 点検の題は「何が起きているか」を、説明は「なぜそうなるか」と「どう直すか」を書く
- ボタンの文は、押すと起きることを書く (「説明を読む」)。状態を書かない (「音: 切」ではなく、アイコンと押し込みで示す)

## 使いやすさ

### コントラスト

WCAG 2.2 の AA を目安にする。

- 文字は、地との比を 4.5 以上にする。18 px 以上の太字 (お金、帯の題) は 3 以上でよい
- 操作する部品の境界 (入力欄の枠、チェックの箱、メーターの外枠) と、意味を運ぶアイコンは、隣の色との比を 3 以上にする
- 札とボタンの枠 (`edge`) と厚み (`lip`) は飾りで、この目安の対象にしない。ボタンは、地の色 (`surface` と草の比は 2.23) と形で見分ける
- 半透明の地の上の文字は、下に草が来た場合と、空が来た場合の両方で計算する

主な組み合わせの比は次のとおりである。
すべての値は [トークンの表](ui-tokens.md) にある。

| 文字 | 地 | 比 |
|---|---|---|
| `ink` | `surface` | 14.53 |
| `ink-sub` | `surface` | 5.51 |
| `ink-sub` | `surface-hud` (下が草) | 5.25 |
| `ink-sub` | `danger-soft` | 4.86 |
| `ink-faint` | `surface` | 5.43 |
| `ink-faint` | `surface-sunken` | 4.72 |
| `gold-ink` | `surface` | 6.00 |
| `on-gold` | `gold` | 6.13 |
| `info-ink` | `surface` | 8.25 |
| `danger-ink` | `danger-soft` | 6.31 |
| `term-text` | `term` | 11.15 |
| `term-sub` | `term-hud` (下が空) | 5.62 |

### フォーカスの見せ方

キーボードで操作しているとき (`:focus-visible`) に、部品のまわりに輪を出す。

- 輪は、太さ 3 px、部品の外側 2 px に離して描く (`outline` と `outline-offset`)。部品の角丸に沿う
- 色は `info-ink` (`#1d4f80`)。`surface` との比は 8.25、草との比は 3.70、空との比は 5.48 である
- 暗い地 (`term`) の中では、色を `term-focus` (`#ffd45a`、比 9.29) に替える。`info-ink` は `term` との比が 1.56 しかない
- 輪は、厚みの影 (`box-shadow`) とは別に描く。押し込んでも輪は消えない
- マウスで押したときは輪を出さない

### キーボード操作

- すべての操作を、Tab、Shift+Tab、Enter、Space、矢印、Esc で行えるようにする。操作する部品は `button` か、Base UI の部品で作り、`div` や `h2` のクリックで作らない
- Tab の順番は、左上の札、右上の札、課題の札、ログ、ボタン列の順にする。課題の札の中は、畳むボタン、点検、今の課題のコピー、「説明を読む」の順である
- 窓とメニューは、開いたら中の最初の部品にフォーカスを移し、閉じたら開いた部品に戻す
- 押す場所の大きさは 24×24 px 以上にする (WCAG 2.2 の 2.5.8)。右下のボタン列と閉じるボタンは 36 px 以上にする
- 3D の畑はマウスで回す。マスの情報はマウスでしか出ないが、同じ値は `ros2 topic echo` で読めるので、キーボードの代わりは用意しない
- 大会モードは、WASD などのキーでロボットを動かす。HUD のボタンにフォーカスがあるあいだは、Space や Enter がそのボタンに効く。ボタンを押したあとは、フォーカスを畑に戻す

### 読み上げ

- 通知は `role="status"`、ログは `role="log"`、点検のまとめの行は `aria-live="polite"` にする
- メーターには、値と目標を `aria-valuenow` と `aria-valuemax` で付ける (Base UI の Progress が付ける)
- アイコンだけのボタンには `aria-label` を付ける
- 画面の言語は `html` の `lang` に入れる (今も入れている)。英語の原文には `lang="en"` を付ける

## 将来のコードエディタの面

将来、受講生がノードの C++ を書くエディタを、画面の上に足す。
今は作らないが、足すときに見た目が割れないよう、方向を決めておく。
エディタのライブラリは、このガイドでは選ばない。

### 面の考え方

エディタの面は、`term` の暗い地にする。
このガイドでは、暗い地の等幅は「ターミナルに出るもの、打つもの」を意味しており、コードはその延長にある。
説明の中のコードブロックと同じ地なので、説明のコードを写してエディタに貼ったとき、同じ物に見える。

エディタのまわり (タブ、分割の持ち手、道具の列) は、生成りの紙の部品で作る。
暗い面を紙の枠で囲む形は、今のコードブロックと課題の札の関係と同じである。

### 置き場所

エディタは畑に重ねず、画面を左右に分けて並べる。
畑は残った領域に縮め、HUD は「配置」の区切りに従って畳む。
エディタが画面の半分を取れば、畑の領域は狭い画面か小さい窓の形になる。
このために、区切りを HUD の領域の幅と高さで決めておく (「区切りを何の幅で決めるか」を参照)。

分割の持ち手は、幅 8 px の `track` の帯にし、中央に 2 px の `control` の線を引く。
フォーカスを受け、左右の矢印で動かせるようにする。

### コードの色分け

エディタの本文は、`term-text` (緑がかった白) ではなく、色味のない `#e8eee4` にする。
`term-text` の緑は、色分けの緑と見分けにくいからである。
色は、`term` の地との比が 4.5 以上になる値を選んだ。

| 役割 | 色 | `term` との比 | 例 |
|---|---|---|---|
| 本文 | `#e8eee4` | 11.14 | 変数の名前、記号 |
| コメント | `#8fa69a` | 5.07 | `// 0.5 秒ごとに呼ばれる` |
| キーワード | `#ffb86b` | 7.72 | `class`、`return`、`auto` |
| 文字列 | `#a5e075` | 8.47 | `"/bot1/cmd_vel"` |
| 数 | `#f5c542` | 8.11 | `0.5`、`10` |
| 型 | `#7cc7ff` | 7.19 | `rclcpp::Node`、`Twist` |
| 関数 | `#d7b8ff` | 7.64 | `create_publisher` |
| プリプロセッサ | `#ff9fc6` | 6.91 | `#include` |
| 行の番号 | `#8fa69a` | 5.07 | |
| 今の行の地 | `#2c3a41` | | |
| 選んだ範囲の地 | `term-raised` (`#445a63`) | 本文との比 6.16 | |

色分けの色は、エディタの面の中でだけ使う。
面の中では、色は構文を表し、「意味の色」(緑は自分のノード) を表さない。
面の外 (タブ、状態の行、点検) では、これまでどおり意味の色を使う。

topic の名前の文字列 (`"/bot1/cmd_vel"`) を、配線図へのリンクにすることは考えられる。
するときも、文字の色は変えず、下線とツールチップで示す。

### 誤りの見せ方

ビルドのエラーは、点検と同じものとして見せる。

- 誤りのある行は、行の番号の左に、点検と同じアイコン (丸に ×、三角に !) を出す
- 誤りの範囲は、波線の下線で示す。色は、エラーが `#ff8a7a` (`term` との比 5.75)、注意が `#ffb43a` (比 7.42) である
- 文は、点検の札と同じく、英語の原文 (コンパイラの出力) と訳の組で出す
- 点検の札の「開く」は、エディタのその行へ飛ぶ。VSCode の中で今している動きを、画面の中のエディタでも同じにする

### タブ

「部品の仕様」のタブを使う。
選んだタブは、地を `term`、文字を `#e8eee4` にし、下のエディタの面とつなげる。
選んでいないタブは、地が `track`、文字が `ink` である。
保存していないファイルは、名前の右に 6 px の `gold` の丸を出す。

### 状態の行

エディタの下に、高さ 24 px の行を置く。
地は `term-raised`、文字は 12 px の `#ffffff` (比 7.27) である。

- 左に、ビルドの状態を Pill で出す (ビルド中は `neutral`、成功は `player`、失敗は `danger`)
- その右に、このファイルから作ったノードが動いているかを、LED と同じ色の 8 px の丸で出す。動いていれば `#5bf06a`、止まっていれば `#999999` にする。丸の横に、ノードの名前か「停止中」を必ず書く
- 右に、行と桁を等幅で出す

### 文字

エディタの文字は、`font-mono` の 14 px、行の高さ 22 px にする。
説明のコードブロック (13 px) より一段大きくするのは、書く時間が長いからである。
合字は切り、タブは空白 2 個で示す (講習のコードの字下げに合わせる)。

## 実装への写し方

### 部品の置き場所

```
web/packages/ui/
  src/
    tokens.css          @theme の定義 (トークンの表の CSS)
    tokens.ts           3D が使う色の定数 (CSS と同じ値)
    fonts/              同梱する書体 (woff2)
    icons/              同梱するアイコン (SVG)
    Button.tsx, Pill.tsx, Meter.tsx, Card.tsx, Dialog.tsx, Sheet.tsx, ...
    Button.stories.tsx, ...
```

画面 (`src/farm`、`src/match`) は、`packages/ui` の部品だけで組み、色や余白の値を直接書かない。
部品に無い見た目が要るときは、画面の側で作らず、`packages/ui` に変種を足す。

### 変種の書き方

変種は tailwind-variants で書く。
変種の名前は、このガイドの名前 (`primary`、`secondary`、`md`、`sm`) をそのまま使う。

```ts

    'aria-disabled:bg-surface-sunken aria-disabled:text-ink-faint aria-disabled:border-line',

      onTerm: 'on-term bg-term-raised text-white border-transparent',

    },
    size: {
      md: 'h-9 px-4 rounded-md text-base shadow-[0_4px_0_var(--lip)] active:shadow-[0_2px_0_var(--lip)] aria-pressed:shadow-[0_2px_0_var(--lip)]',
```

札、ボタン、Pill、コードブロック、ログの行、点検の札、帯は、操作の部品を使わずに自前で作る。

### Storybook に置く見本

部品ごとに、次の見本を置く。

- すべての変種と大きさ
- すべての状態 (通常、ホバー、押し込み中、押し込んだまま、押せない、フォーカス)
- 長い英語の文を入れたもの、長いパスを入れたもの
- 狭い画面の幅 (288 px の札の中) に置いたもの
- 動きを減らす設定を入れたもの
- 畑の上に置いたもの (背景を草の色 `#6cbf45` と空の色 `#9fd8f5` に替えられるようにする)

画面の全体は、記録した `/farm/state` を流し込んだ見本を、1366×820、1000×700、500×380 の三つの大きさで置く。
点検が 4 件ある状態と、ログに原文と訳が並ぶ状態を含める。

## 決めていないこと

次のことは、このガイドでは決めきれていない。

- **丸い書体をどれにするか、どこまで使うか**：M PLUS Rounded 1c を見出しと数字にだけ使う案にした。Zen Maru Gothic も候補で、実際の画面で見比べていない。本文まで丸い書体にする案は採らなかったが、サブセットの大きさを測れば判断が変わりうる
- **3D の粒の色を送り手の色にそろえるか**：「意味の色」に書いた。そろえると、topic の種類ごとの色 (お金の金、看板の桃色) が無くなる
- **CLI と注意が同じ琥珀色でよいか**：今のまま残した。CLI に別の色相を与える案もあるが、空いている色相は紫 (実績) と桃色 (看板) しかない
- **説明を横の紙にするか**：窓のままにする案と比べ、畑が見えることを優先した。幅 480 px では、説明の中の表 (3 列) が狭くなる
- **点検を 1 件だけ開く形でよいか**：すべてのエラーが一度に目に入ることを優先するなら、今の「すべて開く」形に高さの上限だけを付ける案もある
- **句読点をどちらにそろえるか**：画面の文は半角のカンマ、ガイドは読点で、文言の表を直す作業が要る
- **アイコンを自前で描くか、既存の一式を同梱するか**：線の太さと角の丸めだけを決めた
- **大会モードの HUD の配置**：見た目が試作の段階なので、部品の決まり (札、キーの札、Pill) だけを当て、配置は決めていない
- **暗い色調の画面**：VSCode の暗いテーマの中で開いたときも、今は明るい札のままである。畑が明るいので暗い札は合わないと考えているが、確かめていない
